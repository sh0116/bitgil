# 사용자 검증 프로토콜 / User-Testing Protocol

> 로드맵 **M4**의 실행 문서. 이 제품은 근거상 **사람 검토 없는 AI 설명을 학습에 쓰면
> 안 되고**([evidence.md](evidence.md) §1·§2), 자율 대행의 안전이 실증되지 않았다. 따라서
> 사용자 검증은 "좋은지 물어보기"가 아니라 **안전 가설을 반증하려는 실험**이어야 한다.
>
> 원칙: **"Nothing about us without us."** 시각장애 당사자가 참여자이자 공동 설계자다.

## 0. 공통 사항

- **참여자:** 1차 웨지에 맞춰 **학습(인강·도표) 사용자 우선 5명 이상** + 게임 소수(탐색).
  가능하면 성인·아동을 나눠 모집(아동은 §D 별도 프로토콜·보호자 동의 필수).
- **환경:** Pi에서 돌아가는 **웹 클라이언트**가 1차 시험대(NVDA 실기기는 별도). 화면
  공유(getDisplayMedia) + Web Speech.
- **윤리:** 사전 고지·동의, 언제든 중단 가능, 녹취는 별도 동의. 아동은 보호자 동석.
- **측정의 핵심:** 만족도(주관)와 **정확성·오류 탐지(객관)**를 분리해 기록한다. 주관
  만족도만으로는 안전을 판단할 수 없다(사용자는 틀린 설명도 유창하면 신뢰한다).

## 실험 1 — 안내 vs 자율 대행 헤드투헤드

- **가설:** 이 사용자군에서 **안내 우선**(다음 한 수 지목 → 사용자 실행)이 **자율 대행**
  (에이전트가 조작, 사용자 확인)보다 과제 성공률·오류 회복·주관 통제감에서 낫거나 최소한
  대등하다.
- **설계:** 같은 과제 집합(예: 로그인, 특정 영상 재생, 설정 변경)을 두 조건(A=안내,
  B=자율 대행 프로토타입)에서 반복측정, **조건 순서 카운터밸런싱**.
- **측정:** 과제 완료율, 완료 시간, **오조작 횟수와 그중 사용자가 알아챈 비율**,
  개입/도움 요청 횟수, 사후 통제감·신뢰 설문(NASA-TLX 축약 등).
- **결정 규칙(게이트):** 자율 대행이 안전(오조작·미탐지) 지표에서 안내를 유의하게
  이기지 못하면 **M7 자율성 확대를 보류**한다. 이 실험이 자율성 확대의 문지기다.

## 실험 2 — 오류 심기 탐지율 (Hong & Kacorri 패러다임)

- **가설:** 사용자는 AI 설명·안내에 심어둔 오류를 절반 수준에서만 탐지한다
  ([evidence.md](evidence.md) §1). → 감독 기반 안전 모델의 한계를 자기 데이터로 확인.
- **설계:** 해설/안내에 **통제된 오류를 계획적으로 삽입**(예: 실제로 없는 버튼을 지목,
  틀린 수치, 잘못된 상태 보고). 참여자가 "이상하다"고 신고하는지, 신고까지의 단서를 기록.
  오류 유형별(존재하지 않는 요소 / 틀린 값 / 틀린 결과 보고)로 탐지율 분해.
- **측정:** 유형별 **탐지율**, 오탐(정상을 오류로 신고), 탐지에 쓰인 단서(음성 톤·불일치·
  후속 화면).
- **함의:** 탐지율이 낮은 오류 유형은 **자동화 대상에서 제외**하고, 안내 문구에 결과
  예고·불확실성 표기를 강제하는 근거로 삼는다.

## 실험 3 — 확인 대화상자의 실효성

- **가설:** "결제를 확정합니다. 진행할까요?" 같은 확인 절차가 **실제로 안전을 높이는지**,
  아니면 형식적 통과 의례가 되는지. 확인 문구 자체가 AI 생성물이라 §2 오류율의 지배를
  받는다는 위험을 검증.
- **설계:** 되돌릴 수 없는 행동 시나리오에서, (a) 확인 없음, (b) 일반 확인, (c) **결과를
  먼저 경고하는 확인**("이 버튼은 결제를 확정합니다") 세 조건 비교. 일부 시나리오에는
  **잘못된 전제의 확인**(엉뚱한 대상을 확인 요청)을 심어 사용자가 걸러내는지 본다.
- **측정:** 위험 행동 저지율, 잘못된 전제 확인의 통과율, 확인에 걸린 시간·피로.
- **함의:** 확인 문구 설계 표준(결과 예고 필수 여부)과, "확인만으로는 안전하지 않은"
  행동 목록(자동화 원천 제외 대상)을 정한다.

## 실험 4 — 아동 프로토콜 (습득 저해 측정)

- **맥락:** 어린 시각장애 아동에게 도구가 **디지털 자립을 돕는지, 아니면 대신 해줘서
  스스로 익힐 기회를 뺏는지**는 별개 문제다. 대행이 편리할수록 습득을 저해할 수 있다.
- **가설:** 안내 우선(스스로 실행하도록 이끔)이 자율 대행 대비 **기술 습득·유지**에서
  낫다.
- **설계(종단·소규모):** 보호자 동의하에, 동일 과제군을 안내 조건으로 반복 수행하며
  **보조 없이 수행 가능한 비율(자립도)의 변화**를 회차에 걸쳐 측정. 자율 대행 노출군과
  비교(윤리상 제한적·탐색적).
- **측정:** 세션 간 **스킬 유지·자립도**, 좌절/이탈, 보호자 관찰 노트.
- **주의:** 표본이 작고 윤리 제약이 크므로 **정성 관찰 중심**, 인과 주장 금지. 방향성
  신호로만 사용.

## 피드백 → 제품 반영 루프

1. 각 실험은 **사전 등록**(가설·측정·결정 규칙)을 남긴다 — 사후 합리화 방지.
2. 결과는 [evidence.md](evidence.md)에 **[확정]/[초록]/[정황]** 표기로 편입, 결정을 갱신.
3. 안전 지표(오조작 미탐지·위험 행동 저지 실패)는 **릴리스 게이트**: 개선 전 자율성
   확대 금지.
4. 당사자 참여자의 이슈 제기("이 해설이 이상하다")는 1급 기여로 대우(CONTRIBUTING).
