# 앰비언트 데스크톱 코파일럿 / Ambient Desktop Copilot (설계)

> 상태: **비전/설계 문서 (구현 전)**. 이 문서는 빛길의 다음 진화 방향 — 한 앱의 비전
> 내레이터에서, 화면 전체를 함께 보며 사용자의 모든 활동을 공유하는 앰비언트 코파일럿으로 —
> 을 정식화한다. 로드맵의 **M6**에 대응한다.

## 1. 왜 (문제 정의)

스크린리더는 텍스트를 **선형·문자 그대로** 읽는다. 그래서 사용 중 갑자기 나타나는
요소 — Windows 업데이트 팝업, 백신 알림, 애플리케이션 업데이트 배너 — 가 맥락 없이
낭독된다. 익숙하지 않은 사용자, 특히 **어린 시각장애 아동**은 다음을 알기 어렵다.

- 이 알림이 **어디서 왜** 나타났는가 (지금 쓰는 앱? 백그라운드?)
- **중요한가**, 무시해도 되는가
- **무엇을 해야** 하는가
- 그리고 방해로 인해 **하던 작업의 맥락을 잃는다**

핵심은 "더 잘 읽어주기"가 아니라 **주의 관리(attention management) + 맥락 해석**이다.
특정 애플리케이션에 종속되지 않고, 데스크톱에서 벌어지는 모든 활동을 사용자와 함께
"보고" 상황에 맞게 설명·안내하는 곁의 친구.

## 2. 교훈: 실시간성은 비전에서 나오지 않는다

기존 게임 접근성 사례(Minecraft)를 조사한 결과 — 자세한 근거는 §7 참고 — 실시간
접근성은 **픽셀을 LLM에 태워서**가 아니라, 앱이 **내부 상태를 구조화해 노출**하고
**사운드/햅틱으로 즉시 전달**하기 때문에 나온다. LLM이 낄 자리는 오직 *해석·요약*
레이어다. 이를 빛길에 적용하면 **계층형(tiered) 아키텍처**가 된다.

| 층 | 출처 | 지연 | 역할 |
|----|------|------|------|
| 1 | 구조화 접근성 데이터 (UI Automation 트리, 앱/게임 API, 네이티브 Narrator) | 즉시 | NVDA가 이미 담당 |
| 2 | 소니피케이션 / 어스콘 (거리·방향·상태·경보) | 즉시 | 공간·긴급 신호 |
| 3 | **비전 LLM** | 느림(왕복 지배) | 1·2가 못 채우는 **사각지대의 의미 해석만** |

현재 빛길은 사실상 3층만 있다. 실시간 게임이 어려운 이유가 이것이며, 앰비언트
코파일럿의 전제는 **1·2층을 먼저 두고 3층을 선택적으로 호출**하는 것이다.

## 3. 설계 요소

### A. 입력을 픽셀만이 아니라 OS 이벤트로 확장 (1층 확보)
Windows UI Automation 이벤트(포커스 변경·새 창 생성·대화상자 열림), 토스트 알림
리스너, 포그라운드 프로세스 변경을 구독한다. → "무언가 나타났다 + **어느 프로세스** +
텍스트"를 비전/LLM 없이 즉시 감지. 현재의 `capture` 레이어와 **나란히** 붙는 새 입력원.

### B. 인터럽트 트리아지 (이 방향의 심장)
이벤트가 들어오면 다음을 판정한다.
- **출처**: 지금 쓰는 앱인가, 백그라운드인가
- **종류**: 알림 / 모달 대화상자 / 권한 요청 / 오류 / 광고·스캠
- **긴급도·행동필요성**: 작업을 막는가, 결정을 요구하는가, 무시해도 안전한가
- **현재 목표와의 관련성** (§C)

그리고 **출력 정책**을 결정한다: `지금 끼어들어 말하기(interrupt)` / `큐에 미루기(defer)` /
`억제하고 로그만(suppress)`. 이는 이미 존재하는 `SpeechBridge`의 queue/interrupt/defer
정책을, 순진한 텍스트 낭독 대신 **트리아지 결과로 구동**하는 것이다.

> 예: "백신 알림이 떴는데, 지금 하시는 문서 작업과 무관하고 급하지 않아요. 무시하고
> 계속하셔도 되고, 원하시면 제가 닫을게요."

> **구현 상태:** 코어 프로토타입 존재 — `bitgil_core.triage`. `DesktopEvent` →
> LLM 분류(`InterruptTriage`) → **결정론적 안전 정책**(`apply_policy`, 순수 함수) →
> `TriageDecision(interrupt/queue/suppress + 말할 내용)`. 안전 가드레일(스캠 경고,
> 보안 프롬프트 자동억제 금지, 분류 실패 시 조용히 버리지 않고 큐잉)은 LLM과 분리해
> `apply_policy`에 두어 오프라인 단위 테스트한다(`tests/test_triage.py`).

### C. 목표/맥락 추적
사용자가 무엇을 하려는지 롤링 요약으로 유지 → 관련성 판단과 상황 맞춤 설명의 근거.
`SessionContext`를 "앱 단위"에서 "데스크톱·사용자 의도 단위"로 확장.

### D. 크로스 애플리케이션
데스크톱 레벨에서 상시 동작하되, 알려진 앱이 포커스되면 프로파일로 특화. 프로파일
시스템에 `desktop` 프로파일 + 앱(프로세스) 감지를 더한다(구조는 이미 존재).

### E. 양방향·대화형
"방금 뭐야?", "안전해?", "뭘 눌러야 해?", "닫아줘" 같은 질의에 응답하고, UI Automation
invoke / computer-use로 **대신 조작**까지 수행 — 단 §F에 따라 **반드시 확인 후**.

### F. 안전·신뢰 (특히 아동에게 필수)
- 보안 프롬프트(UAC, 권한 요청 등) **자동 클릭 절대 금지** — 항상 사용자 확인.
- **진짜 시스템 대화상자 vs 가짜/스캠 팝업 구분.** 맹인 대상 가짜 백신 사기는 실재
  위협이며, 코파일럿이 이를 경고하는 것 자체가 큰 가치.
- 전체 화면 캡처는 민감 정보 → 온디바이스 처리 우선, 캡처 프레임 비영속(§ SECURITY.md
  정책 계승), 필요 시 리댁션.

### G. 교육 모드
어린/미숙 사용자에게 "이건 알림이고 저절로 사라져요"처럼 **Windows 사용법 자체를 코칭**.
읽어주기가 아니라 곁의 친구가 가르쳐주듯.

## 4. 코드 매핑: 재사용 vs 신규

**그대로 재사용 (대부분 이미 있음):**
- 변화 감지 게이팅 `bitgil_core.change_detect`
- 프로파일 speed 티어 / 프레임 다운스케일 (지연·비용 레버)
- 끼어들기 정책 `SpeechBridge` (queue/interrupt/defer)
- 프로파일 시스템 `bitgil_core.profiles`, 세션 컨텍스트 `bitgil_core.context`
- 프로바이더 추상화 `bitgil_core.providers`

**신규:**
1. **OS 이벤트 소스** (UIA / 토스트 / 프로세스) — 새 입력 레이어 (`capture`와 병렬).
2. **트리아지 모듈** — 이벤트 → LLM 분류 → 출력 정책. ✅ **프로토타입 완료**
   (`bitgil_core.triage`, §3B 구현 상태 참고). 정책 계층은 순수 함수라 오프라인 테스트됨.
3. **목표 추적기** — 사용자 의도 롤링 요약.
4. **안전 분류기** — 시스템 대화상자 / 스캠 / 권한 요청 판별.
5. **액션 실행기** — UIA invoke 등 대리 조작 + 확인 게이트.

## 5. 아키텍처 한 줄 요약

> "한 앱의 비전 내레이터" → **"구조화 OS 이벤트 + 선택적 비전-LLM 해석 + 지능형
> 인터럽트 트리아지를 융합한 앰비언트 데스크톱 코파일럿."**

## 6. 열린 질문 / 리스크

- **지속 비용**: 전체 화면을 상시 비전 LLM에 태우면 비용·지연이 폭발 → 반드시 §2의
  계층형(구조화 우선, 비전은 선택적)으로 억제.
- **트리아지 오판**: 중요한 알림을 억제(suppress)하면 위험 → 보수적 기본값(불확실하면
  최소한 조용한 어스콘으로 존재는 알림), 사용자 조정 가능한 민감도.
- **플랫폼 종속**: UIA는 Windows 전용. 코어(MIT)는 이벤트를 **추상 인터페이스**로 받아
  OS별 어댑터로 분리(Minecraft 모드가 게임별로 하듯).
- **대리 조작의 책임**: 화면을 볼 수 없는 사용자가 잘못된 클릭을 검증할 수 없음 →
  되돌릴 수 없는/보안 행동은 항상 명시적 확인.

## 7. 참고 (조사 근거)

게임 접근성이 실시간을 달성하는 방식 — §2의 교훈 출처:

- **Minecraft 내장 Narrator** (Java Edition): `Ctrl+B` 토글, 모드 All/Chat/System/Off.
  채팅·시스템·UI 텍스트를 OS 음성으로 낭독. (Minecraft Wiki — Options/Accessibility)
- **Minecraft Access 모드** (커뮤니티, Fabric/NeoForge, GPL-3.0): 게임 **내부 상태**를
  직접 읽어 전달 — 좌표 X/Y/Z, 바라보는 블록과 면(`"Stone North"`), 카메라 방향,
  20블록 내 블록/개체 스캔, POI 그룹화·락온, 체력·허기·방어구·산소, 인벤토리 슬롯
  내용. 공간은 **소리로**: 상대 위치 사운드큐(볼륨=거리, 음높이=고도), 낙하 감지,
  물/용암 위치음, 활 조준 보조음. **스크린샷/비전은 쓰지 않는다.**
  (docs.mcaccess.org/features)
