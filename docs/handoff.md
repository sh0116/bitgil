품질 측정을 막는 유일한 문턱은 아닙니다:

> **2026-08-27 실측: 파이에서 Bedrock 비전 경로가 동작합니다.**
> `--provider bedrock`, 리전 `ap-northeast-2`, 모델 `apac.anthropic.claude-3-5-sonnet-20241022-v2:0`.
> 자작 시험지의 막대그래프를 8.4초에 설명하고 인쇄된 네 값을 모두 정확히 읽었으며,
> 값 라벨이 없는 막대는 눈금에서 보간하지 않고 "라벨이 없어 읽을 수 없습니다"로 답했습니다.

즉 **해설 품질·환각률 측정을 지금 시작할 수 있습니다**(§6-2). OmniRoute는 여전히 오너가 정한
실사용 경로지만, 측정을 그것에 묶어 둘 이유는 없어졌습니다. 단, Bedrock은 검증용이며
파이의 자격증명은 로테이션 대기 상태입니다(§7).

아래 §3~§5는 OmniRoute 경로를 이어갈 때 필요한 실측 기록으로 그대로 유효합니다.

Pi에서의 출력은 이렇습니다(2026-08-27, 게이트웨이 v16):

```
게이트웨이 http://localhost:20128/v1 — 콤보 제외 모델 77개

비전 선언 모델 7개 (입력 용량 큰 순, → 표시가 실제 시도 순서):
 →  1. oc/mimo-v2.5-free  (1,048,576 tokens)
 →  2. aug/gemini-3.1-pro-preview  (1,000,000 tokens)
 →  3. ddgw/gpt-5.4-mini  (409,600 tokens)
    4. ddgw/gpt-5.4-nano  (409,600 tokens)
    ...
```

**무엇을 보고 판단하나:**

| 출력 | 뜻 | 다음 조치 |
|---|---|---|
| "프로바이더별"에 OpenRouter 접두어(`or/…`)가 **없다** | 대시보드에 연결했어도 카탈로그에 모델이 안 올라온 것 | 대시보드에서 OpenRouter 모델을 활성화/동기화 |
| 접두어는 있는데 **비전 0** | 게이트웨이가 그 모델들을 비전으로 인정하지 않음 → 우리 후보 필터가 배제 중 | §4의 열린 결정 참조 |
| 비전 목록에 있는데도 전부 실패 | 쿼터·egress IP 차단 | 대시보드에서 쿼터 남은 프로바이더 연결 |

## 3. OmniRoute에 대해 **실측된** 사실 (추측 아님)

1. `auto/*` 콤보 채널은 `/v1/models`에서 **`capabilities.vision`을 절대 선언하지 않습니다.**
   구체 모델만 선언합니다. 그래서 콤보만 믿으면
   `400 No target in combo auto/pro-vision has confirmed vision support`가 납니다.
2. **`capabilities.vision: true`는 주장일 뿐 동작하는 경로가 아닙니다.** ddgw 모델은 플래그를
   달고도 이미지에 `400 ERR_BAD_REQUEST`를 돌려줍니다. 그래서 하나 고르고 끝내면 안 되고,
   실패하면 다음 후보로 넘어가야 합니다(PR #14).
3. 키 없는 무료 풀은 **opencode + felo 둘뿐**입니다(`poolSize 11`이지만 `attemptOrder`는 둘만).
   둘이 죽으면 `auto`와 `auto/best-vision`이 **같은 순서로 같은 실패**를 냅니다.
4. `auto/vision`·`auto/multimodal`은 후보 컨텍스트 한도가 작아 스크린샷을 거부합니다
   (~1225 tokens). 기본값은 `auto/best-vision`(quality 티어는 `auto/pro-vision`).
5. 게이트웨이의 비전 판정은 **id 문자열 조각 매칭**입니다
   (`shared/constants/visionModels.ts`의 `VISION_MODEL_ID_FRAGMENTS`: `gpt-4o`, `gemini-2/3`,
   `claude-3`, `-vision`, `multimodal` …). 의도적으로 보수적이라, 실제로 이미지를 읽는 모델도
   id에 그 조각이 없으면 플래그가 안 붙습니다. `KNOWN_TEXT_ONLY_DESPITE_SYNC`가 mimo-v2.5-pro
   등을 반대로 걷어냅니다. → 즉 **플래그 누락(false negative)이 구조적으로 가능합니다.**
6. 게이트웨이 실행: `npm install -g omniroute` 후 `omniroute`(게이트웨이 + 대시보드, 포트 20128).
   토큰은 `omniroute tokens create`, 변수명은 `OMNIROUTE_API_KEY`(우리 어댑터가 그대로 읽음).
7. **맥에서 실제로 통한 유일한 방법:** 대시보드에서 상위 프로바이더(OpenRouter)를 연결.
   로그인창이 떠서 초기 비번을 넣었더니 동작했습니다. 오너 요청: 이 인증을 나중에 자동화.
   (Bitgil 쪽 몫은 이미 구현 — `OMNIROUTE_API_KEY`/`BITGIL_API_KEY` 자동 픽업.)

## 4. 열린 설계 결정 — 플래그 없는 모델도 시도할까?

§3-5 때문에 `capabilities.vision` 필터가 **실제로 이미지를 읽는 경로를 배제**하고 있을 수
있습니다. 유혹적인 해결책은 "플래그 없는 모델도 그냥 시도"인데, **그냥 하면 안 됩니다**:
이미지를 못 보는 텍스트 모델은 요청을 거부하는 대신 **그럴듯한 화면 설명을 지어냅니다**. 그걸
시각장애인 사용자가 음성으로 듣고 검증할 방법이 없습니다(§CLAUDE.md의 50% 근거).

그래서 만약 이 길로 가려면 최소한:
- 사용자가 명시적으로 켜야 하고(`--allow-unflagged-routes` 같은 옵트인), 기본값은 꺼짐,
- 해설 앞에 "이 모델은 이미지 지원이 확인되지 않았습니다" 고지를 붙이고,
- 그 경로의 결과를 복습 노트 출처에 표시해야 합니다.

먼저 §2의 `--list-routes` 출력을 확보해 **정말 그 상황인지** 확인하세요. 아니라면 이 작업은
필요 없습니다.

## 5. 어댑터의 라우팅 규칙 (구현 완료, `core/bitgil_core/providers/omniroute_provider.py`)

- 우리가 고른 경로가 실패하면 `/v1/models`를 **한 번** 조회해 비전 선언 구체 모델을 **입력 용량
  큰 순**으로 최대 **3개**까지 시도(상한 이유는 인내심이 아니라 해설 턴 안의 **지연**).
- 400/404/415/422/501 = 세션 내 **영구 제외**. 429·5xx = 이번 호출만 건너뜀(쿼터는 리셋됨).
- 401 = 재라우팅 안 함(어떤 경로로도 인증은 해결 안 됨) + 채울 변수명을 알려줌.
  **403은 인증 힌트 없음** — 게이트웨이가 쿼터 소진에도 403을 씁니다.
- 사용자가 `--model`로 지정한 경로는 재라우팅하지 않음(고른 건 사용자, 그 오류가 답).
- 다음 프레임은 죽은 경로에서 시작하지 않음(`_retire_dead_route`).
- 전부 실패하면 시도 횟수 + 마지막 게이트웨이 이유 + 대시보드 주소를 **한 문장**으로 낭독.
