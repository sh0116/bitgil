# 라이선스 전략 / Licensing

기획서 섹션 8 기준. 대회 라이선스 검정에 대비한 이중(삼중) 구조.

| 대상 | 라이선스 | 근거 |
|------|----------|------|
| 애드온 본체 (`addon/`) | **GPLv2** | NVDA가 GPLv2이며 애드온은 NVDA 프로세스 내에서 동작. AI-content-describer도 동일 노선 |
| 코어 로직 (`core/`) | **MIT** | NVDA 비종속 순수 로직 — Orca 등 타 스크린리더/독립 앱으로의 이식성 확보 |
| 프로파일 데이터 (`profiles/`) | **CC BY 4.0** | 코드가 아닌 데이터/콘텐츠 |

## 왜 분리하는가
GPLv2와 MIT를 물리적으로 다른 패키지로 분리하면, 코어 로직을 GPL 의무 없이 재사용할 수
있다. 애드온이 코어를 포함(번들)해 배포될 때 결합 저작물은 GPLv2를 따르지만, 코어 자체는
MIT로 독립 배포·재사용 가능하다.

## CI 라이선스 검사
`license-checker`(또는 파이썬 생태계 등가물)를 CI에 포함해, 의존성 라이선스 충돌을
자동 검출한다. 대회 라이선스 검정 리포트의 근거 자료로 사용.

## API 키 / 프라이버시
- 화면 캡처는 로컬 처리 우선, 외부 전송은 명시적 동의 기반.
- API 키는 절대 저장소에 커밋하지 않는다(`.gitignore`로 차단). BYO API Key.
- 게임 화면 전송에 대한 개인정보 고지를 애드온에 내장.
